# Claims: surface the implicit ones, numbered

Misalignment hides in implicit claims: things a sentence assumes but never says. Claudes sideload these implicit claims during design, planning, writing, and prioritization tasks, and these implicit claims pollute product sense and cause massive misalignment.

The user can't correct what isn't written, so write all of it, numbered, and let them strike by number to get onto the same page.

1. **Quote the text verbatim** (yours or theirs), so both of you are pointing at the same words.
2. **List every claim in STE**, one idea per line: explicit claims first, then implicit ones. Number them `claim-1` … `claim-n`. Implicit claims matter most.
3. **Count the nouns the user named.** Each noun in their request (HTML, sections, interactions) is an explicit claim that the work holds it; check each one has a place. A field set or scope copied from an earlier tool carries that tool's narrower question as an implicit claim.
4. **Then list APC** (axioms, principles, cruxes), with numbering restarting at `apc-1`, so a correction can name `claim-n` or `apc-n` with no ambiguity.
5. **Take the strikes as given.** "5, 9, and 11 are incorrect" means rebuild from their negations. Don't defend, don't guess a new belief wholesale: list the claims of your corrected sentence again, and repeat until none is struck.
6. **Don't ratchet** a corrected belief into a rule or skill until the user says it's right. Wording it is part of getting it right.
7. **No hedges.** State a limitation once, where it applies.
